# README — เริ่มต้นใช้งาน Second Brain นี้ใน Obsidian

> [[00 หน้าแรก|← กลับหน้าแรก]]

## วิธีเปิดใน Obsidian
1. เปิด Obsidian → "Open folder as vault" → เลือกโฟลเดอร์ **รายงานและข้อเสนอแนะ กสม** นี้ทั้งโฟลเดอร์ (ไม่ใช่โฟลเดอร์ย่อย)
2. ลิงก์ทั้งหมดในโน้ตใช้รูปแบบ `[[ชื่อไฟล์]]` (wikilink) ซึ่ง Obsidian จะ resolve เองแม้ไฟล์จะอยู่คนละโฟลเดอร์ ตราบใดที่เปิดทั้งโฟลเดอร์นี้เป็น vault เดียว
3. แนะนำปลั๊กอิน (ไม่บังคับ): **Dataview** (ทำ query แบบไดนามิกเพิ่มเติมได้), **Templater** (ใช้แม่แบบใน `05 แม่แบบ (Templates)`), **Tag Wrangler** (จัดการแท็ก)

## โครงสร้างโฟลเดอร์
```
รายงานและข้อเสนอแนะ กสม/
├── 00 หน้าแรก.md                      ← เริ่มที่นี่ (MOC หลัก)
├── README - เริ่มต้นใช้งาน.md
├── 01 โปรเจกต์ (Projects)/            ← งานที่กำลังทำอยู่ตอนนี้
├── 02 ประเด็นสิทธิ (Areas)/           ← 23 หมวดประเด็นสิทธิ (ถาวร) แบ่งเป็น 4 กลุ่ม + หมวดเพิ่มเติม
│     แต่ละโน้ตรวม: แนวโน้มสถานการณ์รายปี 2564-2568 + รายการกรณีตรวจสอบที่เกี่ยวข้อง + งานวิจัยที่เกี่ยวข้อง
├── 03 กรณีตรวจสอบ (Case Notes)/       ← 1 โน้ตต่อ 1 กรณี (แยกตามปี) ลิงก์กลับไปยัง PDF/DOCX ต้นฉบับ
├── 04 คลังงานวิจัย (Research)/        ← 1 โน้ตต่องานวิจัย 1 ชิ้น
├── 05 แม่แบบ (Templates)/             ← แม่แบบสำหรับสร้างโน้ตใหม่
│
│  (ของเดิม — ไม่ถูกแก้ไข/ย้าย)
├── ปี 2563 .. ปี 2569/                ← เอกสารต้นฉบับ (PDF/DOCX) ตามเดิมทุกไฟล์
├── รายงานประเมินสถานการณ์/
├── index.html, auto_categorize.gs, *.xlsx  ← เครื่องมือ/แดชบอร์ดเดิมของคุณ ยังใช้งานได้ตามปกติ
```

## หลักการออกแบบ
- **ไม่แตะไฟล์เดิมเลย** — ปี 2563-2569, รายงานประเมินสถานการณ์, index.html, ไฟล์ xlsx ทั้งหมดอยู่ตำแหน่งเดิม ไม่ถูกย้าย เปลี่ยนชื่อ หรือแก้ไข
- **โน้ตกรณีตรวจสอบ** สร้างจากไฟล์ `สังเคราะห์ข้อมูลรายงานตรวจสอบของ กสม. 2563 - 2569.xlsx` (380 กรณีที่มีเลขที่รายงาน) จับคู่กับไฟล์ต้นฉบับในโฟลเดอร์ปีต่างๆ อัตโนมัติได้ 361 กรณี (95%)
- **โน้ตประเด็นสิทธิ (Areas)** ผสานข้อมูลจากไฟล์สังเคราะห์สถานการณ์ 2564-2568 เข้ากับรายการกรณี/งานวิจัยที่เกี่ยวข้อง เพื่อให้แต่ละหมวดเป็นหน้ารวมความรู้ (MOC) ของประเด็นนั้นๆ
- **การจัดหมวดหมู่กรณี** ใช้การจับคำสำคัญ (keyword matching) จากชื่อเรื่อง/พฤติการณ์/สาเหตุ โดยอิงหมวดหมู่เดียวกับที่ใช้ใน `auto_categorize.gs` ของคุณ เป็นการจัดหมวดแบบร่างเบื้องต้น (heuristic) — กรณีหนึ่งอาจถูกแท็กได้หลายหมวด และควรตรวจทานอีกครั้งหากต้องการความแม่นยำสูง (แก้ไขได้ตรงๆ ที่ frontmatter `areas:` ของแต่ละโน้ต)
